Rail Operations Lab

Timetable quality and corridor resilience • Independent learning portfolio • Eric Tran

All inputs are invented. This educational model is not calibrated to Melbourne's network and cannot establish operational feasibility or safety.

1. Validate before modelling

The single-day timetable extract passes structural, reference and time-order checks. The SQL spacing screen finds 3 departures below an illustrative 240-second threshold. These are review flags, not proven infrastructure conflicts.

2. Compare four operating scenarios

200 replications per scenario, seed 20261118. The same random streams support paired comparisons. Delays are measured against each scenario's own scheduled terminal arrival.

What would I discuss with a planner?

The three-minute scenario schedules trains every 180 seconds against an assumed 210-second combined block occupancy and clearance. It creates structural queueing in this toy model. First check resource assumptions and the timetable before increasing frequency.

Recovery time can improve arrival punctuality partly by allowing a longer journey. Lower dwell variability tests a different mechanism. Neither scenario establishes a real-world benefit without observed run and dwell distributions, passenger demand, and operator review.

What the model omits

Opposing movements, junctions, signals, braking curves, station capacity, rolling stock, crew, cancellations, passenger loading and finite upstream storage. Trains retain timetable order. No warm-up or steady-state claim: this is a finite cohort of 16 trains initially entering an empty corridor.

Audit trail

CSV metrics, event traces, parameter values and Monte Carlo standard errors accompany this report. Standard errors describe simulation sampling noise, not uncertainty about real operations.
